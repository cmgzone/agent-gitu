## Delivery sequence and acceptance gates

1. **Organization and authority.** Director/CEO/team-leader/employee roles, departments, stable reporting IDs, cycle prevention, explicit authority and resource restrictions. Migrate existing staff without disabling their established work. Verify scope, director-only authority changes, manager restrictions and runtime enforcement.
2. **Boardroom.** Durable meetings and participants, agendas, runtime speaking leases, hand requests and reasoned queue decisions. Run bounded discussions through existing Company/Cowork execution, account every model attempt, and stop on pause, limits or interrupted ownership. Verify turn exclusivity, lease expiration, unauthorized speech, objections, recovery and audit records.
3. **Scheduling, summaries and action items.** Immediate/scheduled/emergency meetings, safe task checkpoints, attendance states, history search, confirmed versus proposed decisions, linked real missions and director attention. Verify no duplicate wakeups or assignments and preserved unrelated work.
4. **Handbook and onboarding.** Versioned approved guidelines separate from enforcement rules and suggestions; role/tool orientation, moderated onboarding meeting, practical mission assessment and activation/retraining gates. Verify onboarding never enlarges grants and policy changes invalidate affected checks.
5. **Workflow definitions and execution.** Immutable versions, typed inputs/outputs, dependencies/conditions, approvals, bounded parallelism, retry/timeouts and recoverable runs. Dispatch actual Cowork missions and retain TaskLedger/evidence readiness for coding. Verify branch/dependency behavior, worker admission, approvals, stale directions and recovery.
6. **Workflow studio.** Connected canvas with pan/zoom/layout, node/edge inspectors, actual statuses and handoff evidence. Side-effect-free validation/simulation identifies missing agents, skills, connections, inputs, permission/approval gates and graph defects. Contextual fixes use actual app routes and revalidate after return. Verify simulation makes no external calls and is never labeled live completion.
7. **Calendar and director overview.** Opt-in authorized Google Calendar event create/update/cancel, timezone-aware schedules, persisted external IDs and idempotent recovery. Overview links real meetings, workflows, blockers, decisions and executive summaries. Verify mocked provider expiry/errors/retries and authorized live acceptance separately.
8. **Release.** Regression checks, compilation/lint, responsive browser flows, local Windows package verification and outstanding native/provider/platform gates. Rebuild installers after the new implementation passes; merge main only after release checks.

## State machines

- Meetings: scheduled → active → summarizing → completed; cancellation and interrupted recovery remain explicit. Participation: listening, hand-raised, queued, speaking, muted, excused. Only a current durable lease permits contribution.
- Onboarding: identity → orientation → meeting → resources → assessment → active, with blocked/retraining states and recorded evidence. Existing staff migration retains active status.
- Decisions: proposed → under-review → approval-required/approved/rejected → executing → completed/failed. Approval binds an immutable action digest and never overrides tool authorization.
- Workflow definitions: draft → approved → archived. Runs: queued → running → waiting/blocked → completed/failed/cancelled. Steps: ready/running/waiting/blocked/failed/completed/skipped. Simulations have separate records and cannot settle live steps.

## Workflow, simulation and Calendar checkpoint — 14 October 2026

Workflow definitions now have immutable draft/approved/archived versions, typed inputs/outputs, explicit field bindings, dependencies, equality conditions, agent/resource requirements, bounded parallelism, sessions, attempts and timeouts. Approved runs dispatch actual Cowork missions through the existing Company queue and worker locks. Produced results must match the output schema before dependent tasks are admitted. Approval steps bind the director's decision to a digest of the exact run, version, direction, step and received input. Existing tool authorization, model spending and Coding/TaskLedger completion checks remain in force; approval never adds grants.

Retries preserve the prior mission IDs and require director review, an available attempt and reconciliation of uncertain external actions. Cancellation, timeout, changed direction and revoked assignment authority stop the specific workflow missions while preserving unrelated work. Permissions and timeouts are checked before model calls and tools. Durable mission pointers avoid scanning completed run history on every model call, and scheduler queries omit settled runs. Both owner start requests and native agent retries are idempotent within their trusted request/job/message. Employee run inspection redacts other employees' handoff content; the director retains the full evidence view.

The themed Workflow studio has separate Design, Simulation and Live execution modes, draggable nodes, connected handoffs, pan/zoom, graph arrangement, step/resource/schema inspectors, reusable copies, version approval/archive controls, actual run histories, exact-input approvals and retry/cancellation controls. Simulation uses supplied sample outputs and local configuration/last recorded connector state; it makes no model or external service calls, creates no missions and changes no grants. Its records cannot complete live work. Problems link to the real Team, Resources, Settings or workflow inspector sections, and requirements revalidate after returning from a contextual fix. Real execution rechecks current permissions and connector authorization.

Calendar uses the existing protected Composio OAuth accounts and fixed Google Calendar API paths. The director opts individual meetings into an authorized account/calendar, with optional automatic schedule and cancellation synchronization. The transport disables mutating retries and rechecks Company authorization immediately before submission. Deterministic event IDs and private ownership markers allow GET reconciliation of lost create/update/delete responses without duplicate events. Updates use ETags and the durable Company action journal. Calendar UI supports explicit-offset/IANA-zone schedule editing, displays pending updates separately from synchronized results, and offers an explicit director refresh for remote edits. No participant email invitations are authored by this integration. Removing a remote event does not silently recreate it.

Primary API references reviewed: [Composio OAuth proxy execution](https://docs.composio.dev/reference/v3/api-reference/tools/postToolsExecuteProxy) and [Google Calendar event insertion and authorization](https://developers.google.com/workspace/calendar/api/v3/reference/events/insert). The implementation also checks the installed SDK's typed proxy transport rather than assuming tool slugs or raw credential access.
