Understand the project first

The project guard walks up from your working directory until it finds a repository marker, then treats that root as the entire writable world. Reads can wander outside it; writes cannot.

The code index turns the repo into something an agent can actually navigate: exported symbols, their call sites, and the files that reference them. That is why the first thing you see is a read, not an edit.

Why this matters

A wrong guess in an unbounded agent costs you a refactor. A wrong guess inside a locked scope costs you one reversible diff you can read before you commit.

A plan you can argue with

Before the first edit, the task ledger records the steps it intends to take and the criteria it will be judged against. Both live in the task state, not in a chat window that scrolls away.

  • step 1Read the targetLocated the failing assertion in src/server/app-auth.ts.
  • step 2ReproduceRan the focused test and captured the failure output.
  • step 3FixSmallest change that makes the test pass, nothing else.
  • step 4VerifyFull suite plus typecheck, both green.

One focused change at a time

Edits are deliberately small. Here is the shape of a real change it produced, with the diff it was willing to stand behind:

  public authenticated(): boolean {
-   return Boolean(this.account());
+   if (this.requiresEmail() && !this.account()?.email) return false;
+   return Boolean(this.account());
  }

No drive-by refactors, no renamed variables “while we were in there”, no formatting sweep across untouched files. If a change is large, it gets split into several steps.

The evidence gate

This is the part that changes how you can trust the agent. A criterion cannot be marked satisfied by the agent deciding it is satisfied. It needs a recorded verification result.

Evidence gate outcomes
SituationWhat happens
A command passesCriterion is claimed with that command as proof
A command failsTask stays open; the agent must fix or report
No check existsCompletion is refused and the gap is named
UI changeA screenshot or DOM probe is the evidence

Git and review

The Git panel shows the branch, the diff, and the working tree for whatever project is locked. Nothing is committed for you, and no branch is pushed without you asking.

That makes review the default: the diff is the artifact, the evidence is attached to it, and the commit is your decision.
